[0:00 - 0:40]  PROBLEM
-----------------------
[VISUAL: Show a fake job offer letter on screen]

Every day, people receive job offers, freelance contracts, and vendor proposals
that look real -- but aren't. Verifying one means checking company registries,
WHOIS records, SSL certificates, social sentiment, and document metadata --
across a dozen tools -- in 30 to 60 minutes.

Most people don't do that. They guess. Scammers know it.

That's exactly the gap TrustLens AI closes.


[0:40 - 1:20]  WHY AGENTS?
----------------------------
[VISUAL: Show assets/cover_page_banner.png]

Fraud investigation is inherently multi-domain. A single query needs a company
check, a domain analysis, a sentiment scan, AND a document review -- simultaneously,
from different data sources.

One LLM prompt can't do this reliably. It hallucinates. It misses signals.

A team of specialized agents can. Each agent owns one domain, uses real tools,
and returns structured evidence. A coordinating agent then synthesizes everything
into a single, quantified verdict.

Agents aren't just helpful here -- they're the only architecture that works.


[1:20 - 2:20]  ARCHITECTURE
-----------------------------
[VISUAL: Show assets/architecture_diagram.png]

TrustLens runs as a directed Workflow graph on Google ADK. Every request first
hits the security_checkpoint -- a pure Python node that runs before any LLM.
It blocks prompt injections, bans .mil and .gov domains, and scrubs PII like
SSNs and credit cards before they reach the Gemini API.

Safe inputs go to the Coordinator -- an LlmAgent that decides which of five
specialized sub-agents to call: company_agent, website_agent, social_agent,
document_agent, and scam_agent. These agents call a FastMCP tool server --
running as a subprocess -- for real data: WHOIS records, SSL certs, DNS, PDF
metadata, and more.

The evidence feeds into a risk_assessment agent that scores Trust, Risk, and
Confidence. If confidence is low or red flags are critical, the workflow physically
pauses using ADK's RequestInput -- asking a human to approve before the report is
released. Finally, the explainability agent writes the professional Markdown report.

[4:10 - 4:45]  THE BUILD
--------------------------
[VISUAL: Show app/agent.py -- the workflow edges block]

Built with Google ADK in Python. The core primitives used:

  Workflow        -- the directed investigation graph
  LlmAgent        -- 8 specialized agents on gemini-2.5-flash
  AgentTool       -- sub-agents callable as tools by the coordinator
  McpToolset      -- 14 investigation tools via FastMCP subprocess
  RequestInput    -- the Human-in-the-Loop pause mechanism
  ctx.state       -- shared session memory across all nodes, backed by SQLite

All data between agents is typed with Pydantic -- EvidenceItem, RiskAssessment,
SecurityEvent -- enforcing strict contracts at every stage. Deployable to Vertex
AI Agent Engine with the included Terraform setup.
